# کتابخانه محاسبات عددی و ماتریسی

فایل‌ها: `algebra.py` (پیاده‌سازی)، `test_algebra.py` (تست‌ها).
اجرای تست‌ها: `python -m unittest -v test_algebra`

## ساختار وراثت

```
AlgebraicElement (ABC)
├── Integer
├── Complex
└── Matrix
```

`AlgebraicElement` یک کلاس انتزاعی است و قرارداد مشترک `__add__`، `__mul__` و `__neg__` (متدهای abstract) را تعریف می‌کند؛ ساخت مستقیم نمونه از آن `TypeError` می‌دهد. هر سه کلاس `Integer`، `Complex` و `Matrix` از آن ارث می‌برند چون هر سه جمع، ضرب و قرینه دارند. `Matrix` «نوعی عدد» نیست، بنابراین از `Integer` یا `Complex` ارث نمی‌برد و رابطه‌اش با آن‌ها «شامل بودن» است (خانه‌های ماتریس عدد هستند).

## تفاوت `@staticmethod` و `@classmethod`

- `@classmethod` پارامتر `cls` می‌گیرد و می‌داند با کدام کلاس صدا زده شده است. در `Integer.from_string`، `Complex.from_string` و `Matrix.make_matrix_from_string` نمونه با `cls(...)` ساخته می‌شود، پس سازنده‌ی جایگزین (alternative constructor) است و برای زیرکلاس‌ها هم درست کار می‌کند (زیرکلاس را برمی‌گرداند).
- `@staticmethod` نه `self` دارد و نه `cls`؛ تابعی معمولی است که فقط برای مرتب‌بودن در فضای نام کلاس قرار گرفته است. متدهایی مثل `get_ith_row`، `is_unit_matrix` و `make_unit_matrix` به وضعیت کلاس نیاز ندارند و ماتریس را به‌عنوان آرگومان می‌گیرند. `make_unit_matrix` هم از `Matrix` صریح استفاده می‌کند.

## چرا `__sub__` فقط در کلاس پایه است؟

تفریق برای هر سه نوع یک تعریف ریاضی دارد: `a - b = a + (-b)`. چون هر زیرکلاس قبلاً `__add__` و `__neg__` را دارد، نوشتن دوباره‌ی تفریق در هر کلاس کد تکراری است و احتمال ناهمخوانی ایجاد می‌کند. با نوشتن یک‌باره در `AlgebraicElement`، همه‌ی انواع (و هر زیرکلاس آینده) بدون هیچ کدی تفریق را به ارث می‌برند (استفاده‌ی مجدد از کد). همین باعث می‌شود `scalar - matrix` هم کار کند: `scalar + (-matrix)`.

## تصمیم‌های طراحی

- فیلدها خصوصی (`__x`) و ویژگی‌ها با `@property` فقط‌خواندنی‌اند. `Matrix` اعضا را در یک `tuple` کپی‌شده نگه می‌دارد، پس تغییر لیست ورودی یا خروجی روی ماتریس اثر ندارد.
- `int` فقط برای محاسبه‌ی درونی است؛ همه‌ی خروجی‌ها شیء `Integer`/`Complex` هستند. `bool` به‌عنوان عدد پذیرفته نمی‌شود.
- در `scalar + matrix` و `scalar * matrix`، `Integer`/`Complex` مقدار `NotImplemented` برمی‌گردانند تا پایتون `Matrix.__radd__` / `__rmul__` را صدا بزند.
- عملوند نامعتبر (مثل `"3"` یا `3.0`) `TypeError` و ابعاد ناسازگار `ValueError` می‌دهد؛ اندیس نامعتبر `IndexError`.
- `multiply(a, b)` فقط `a * b` را برمی‌گرداند و از Duck Typing استفاده می‌کند (بدون `isinstance`).
- از `eval` استفاده نشده است؛ رشته‌ها با `re.fullmatch` اعتبارسنجی می‌شوند.
